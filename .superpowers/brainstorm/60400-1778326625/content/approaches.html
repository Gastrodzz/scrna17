Three Approaches to the Rebuild

Pick the one that matches your risk tolerance and timeline

A

Big Bang Rewrite

Rebuild DE, Enrichment, and consolidate Networks all at once in one large PR.

Pros

  • Cleanest result
  • No temporary inconsistency

Cons

  • High risk — nothing works until it's all done
  • Hard to test incrementally
  • Long timeline
B

⭐ Phased Rebuild (Recommended)

Three independent phases, each shippable on its own:

  • Phase 1: Rebuild DE from scratch — fix all methods, downsampling, reproducibility. Remove AI.
  • Phase 2: Rebuild Enrichment — fix all database wiring, proper packages, all visualizations.
  • Phase 3: Consolidate Networks — remove duplicates, move pathway network viz into Enrichment.

Pros

  • Each phase independently testable
  • Lower risk per phase
  • Can stop after Phase 1 if needed

Cons

  • Some temporary duplication between Phase 1 and 3
C

Minimal Bug Fix

Patch the existing DE and Enrichment modules in-place. No restructuring.

Pros

  • Fastest to ship
  • Minimal code surface changed

Cons

  • Doesn't solve architecture problems
  • Duplication remains
  • Fragile — same bugs will recur
